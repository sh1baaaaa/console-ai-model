# console-ai-model

Минималистичный консольный чат с языковой моделью через [OpenRouter](https://openrouter.ai).
Проект запускается одной командой, читает ввод из терминала, отправляет его в выбранную
модель и печатает ответ.

## Возможности

- Интерактивный диалог в терминале в бесконечном цикле
- Выбор любой модели, доступной в OpenRouter, через переменную окружения
- Выход по командам `exit` и `quit`, а также по `Ctrl+C` и `Ctrl+D`
- Пустой ввод игнорируется, ошибки запроса не роняют процесс, а печатаются как текст

## Стек

- Python 3.10+
- [openrouter](https://pypi.org/project/openrouter/) как клиент API
- [python-dotenv](https://pypi.org/project/python-dotenv/) для загрузки конфигурации

## Структура проекта

```
console-ai-model/
├── .env               # ключ API и имя модели
├── README.md
└── src/
    ├── __main__.py    # точка входа, вызывает run()
    ├── cli.py         # цикл чтения ввода и вывода ответов
    ├── llm.py         # отправка сообщения в модель
    └── config.py      # загрузка .env и создание клиента
```

Поток данных простой: `__main__.py` вызывает `run()` из `cli.py`, тот передаёт строку
пользователя в `send_message()` из `llm.py`, а `llm.py` берёт готовый клиент и имя модели
из `config.py`.

## Установка

```bash
git clone https://github.com/sh1baaaaa/console-ai-model.git
cd console-ai-model

python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

pip install openrouter python-dotenv
```

## Настройка

Создайте файл `.env` в корне проекта:

```env
OPENROUTER_API_KEY=sk-or-v1-ваш_ключ
OPENROUTER_MODEL=openai/gpt-4o-mini
```

`OPENROUTER_API_KEY` берётся в личном кабинете OpenRouter, в разделе Keys.
`OPENROUTER_MODEL` это идентификатор модели из каталога OpenRouter, например
`anthropic/claude-sonnet-4`, `openai/gpt-4o-mini` или `google/gemini-2.0-flash-001`.

Файл `.env` содержит секрет, поэтому его не следует коммитить. Добавьте в `.gitignore`:

```gitignore
.env
__pycache__/
.venv/
.idea/
```

## Запуск

```bash
python src/__main__.py
```

Модули импортируют друг друга по коротким именам (`from cli import *`), поэтому каталог
`src` должен быть в `sys.path`. Запуск файла напрямую это обеспечивает. Альтернативный
вариант:

```bash
cd src && python .
```

Пример сессии:

```
Chat with AI model started
You: привет, кто ты?
Bot: Привет! Я языковая модель, отвечаю на вопросы и помогаю с задачами.

You: exit
Bye!
```

## Ограничения текущей версии

Проект намеренно небольшой, поэтому ряд вещей пока не реализован:

- Нет истории диалога: каждое сообщение уходит в модель отдельно, без предыдущего контекста
- Нет системного промпта и настроек генерации (temperature, max_tokens)
- Нет потокового вывода ответа, текст появляется целиком после ответа модели
- Нет файла зависимостей (`requirements.txt` или `pyproject.toml`), библиотеки ставятся вручную
- Нет обработки отсутствующих переменных окружения: при пустом `OPENROUTER_API_KEY`
  ошибка всплывёт только на первом запросе
- Ошибки запроса возвращаются как обычный текст ответа, отличить их от ответа модели
  можно только по префиксу `Error sending message:`

## Возможные улучшения

- Хранить список сообщений и передавать его в каждый запрос, чтобы получить настоящий диалог
- Команда очистки истории, например `/reset`
- Стриминг ответа для ощущения живой печати
- Валидация конфигурации на старте с понятным сообщением об ошибке
- `requirements.txt` или `pyproject.toml` и оформление `src` как пакета с относительными импортами
- Аргументы командной строки для выбора модели и системного промпта
